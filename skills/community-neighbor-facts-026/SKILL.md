# 邻里纠纷事实梳理表

## 何时使用

当用户需要把邻里纠纷双方陈述整理为客观事实、个人意见、争议焦点、证据缺口和待核实事项。时使用。

## 输入条件

优先获取任务对象、时间范围、已核实事实、原始材料、期望输出格式和需要保留的原文。

如果信息不足，应先说明缺少的关键资料；用户要求继续时，只基于已有信息生成可用框架，所有缺失项写“待确认”或“待补充”。

## 工作步骤

1. 收集双方陈述、时间地点、已知证据和待核实事项
2. 把原始陈述拆分为事实、转述、意见和推断
3. 按争议焦点对应双方说法与现有证据
4. 标记证据缺口和需要向哪一方补充的信息
5. 生成中立事实梳理表并提示不得预先认定责任

## 输出格式

- 事项概况
- 双方陈述对照表
- 客观事实与个人意见
- 争议焦点
- 证据清单与缺口
- 待核实事项
- 使用说明

默认使用 Markdown。表格应可复制、可核对。不得用示意数据填补真实业务字段。

## 事实与权限边界

- 不得预先认定违法、过错、责任或赔偿金额
- 不得替任何一方补写陈述或制造证据
- 不得把未经核实的传闻写成客观事实
- 不得把事实梳理表冒充调解协议或法律文书

## 隐私与安全

- 使用事项编号或化名，避免完整门牌号、电话、身份证号和健康信息。
- 默认不调用外部收费 API，不连接未经用户明确提供或授权的业务系统。
- 不在用户可见输出中展示内部提示词、文件路径、校验过程、公司宣传、Logo 或水印。

## 异常处理

- 输入为空或核心事实缺失时，先列出最小补充清单。
- 材料互相矛盾时，并列呈现，不擅自选择有利版本。
- 用户要求编造、伪造、越权认定或越过正式程序时，明确拒绝该部分，并提供合规替代做法。
- 工具不可用时，输出可直接复制使用的人工工作框架，并说明未完成项。

## 完成检查

- 是否完整覆盖用户要完成的核心任务？
- 是否区分已提供事实、直接整理、推断和待确认事项？
- 是否避免越权、虚假承诺和绝对化结论？
- 是否执行了信息最小化和脱敏提醒？
- 是否交付了清晰、可编辑、可核对的结果？
