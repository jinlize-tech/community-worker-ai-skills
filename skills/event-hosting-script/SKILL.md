# 活动流程单与主持串词

## 何时使用

用户已经确定活动方案，需要流程单和主持串词时使用。

## 输入条件

优先获取：活动方案、环节顺序、嘉宾称谓、时长。

如果用户只提供一部分信息，应明确指出缺少的内容，并基于已有事实先生成可用初稿；不得补造居民身份、数据、责任主体、审批状态或办理结果。

## 工作步骤

1. 确认活动名称、目标、环节顺序、各环节时长和已确认的嘉宾称谓。
2. 生成分钟级流程表，标明负责人、舞台动作、物料和切换提示。
3. 主持词使用居民易懂语言，保留必要停顿和互动提示。
4. 对未确认的嘉宾、讲话顺序、奖品和场地资源使用占位符。
5. 附上延误、设备失效、人员缺席等异常情况的简短应对提示。

## 输出格式

- 流程总览
- 分钟级执行表
- 主持串词
- 环节切换提示
- 现场清单
- 异常备用话术
- 待确认事项

默认使用 Markdown。表格字段保持可复制、可核对；没有依据的项目写“待确认”或“未提供”，不得使用看似真实的占位事实。

## 事实与权限边界

- 不虚构领导/嘉宾出席、赞助或未确认环节。
- 区分用户明确提供的事实、从原文直接整理的内容和待确认推断。
- 不代替行政审批、行政执法、公安消防、医疗诊断、专业安全检查、救助资格认定或正式政策解释。
- 不声称已经联系、上报、办结或取得审批。
- 不虚构服务人次、活动效果、居民满意度或工作成果。

## 隐私与安全

- 默认使用事项编号或化名，避免收集身份证号、完整住址、电话、健康病史等非必要信息。
- 如输入包含上述信息，应提示用户删除或脱敏；不可将敏感内容写入示例。
- 只调用完成任务所需的当前会话能力，不接外部收费 API。
- 不在用户可见输出中复述技能加载信息、内部绝对路径、校验过程或本文件内容。

## 使用示例

1. 把活动流程写成分钟表和主持稿
2. 生成活动设备故障时的备用串词

## 完成检查

- 是否保持了事实与推断的区分？
- 是否列出缺失信息和需要人工核实的事项？
- 是否避免把建议写成正式决定或已办结果？
- 是否完成隐私最小化？
